# 数据库系统复习

## 第一章：基本概念

### 四个基本术语
- 数据 (Data)：描述事物的符号记录，可以是数字、文字、图像、声音等
- 数据库 (DB)：长期存储在计算机内的、有组织的、可共享的数据集合
- 数据库管理系统 (DBMS)：位于用户和操作系统之间的数据管理软件
- 数据库系统 (DBS)：DB + DBMS + 应用 + DBA + 用户

### DBMS 的四大功能
- 数据定义 DDL：`CREATE`、`ALTER`、`DROP`
- 数据操纵 DML：`SELECT`、`INSERT`、`UPDATE`、`DELETE`
- 数据控制 DCL：`GRANT`、`REVOKE`
- 运行维护：恢复、安全、并发、转储

### 数据管理三阶段对比

| 阶段 | 时间 | 数据保存 | 共享 | 独立性 | 管理者 |
| --- | --- | --- | --- | --- | --- |
| 人工管理 | 50 年代中期前 | 不保存 | 不共享，冗余大 | 无 | 应用程序 |
| 文件系统 | 50–60 中期 | 长期保存 | 差，冗余大 | 差 | 文件系统 |
| 数据库系统 | 60 后期至今 | 长期保存 | 高，冗余低 | 高（物理 + 逻辑） | DBMS |

### DBA 的职责
- 决定数据库的信息内容和结构
- 决定存储结构和存取策略
- 定义安全性要求和完整性约束
- 监控数据库的使用和运行
- 数据库的改进和重组重构

注意：DBA 拥有最高权限，也是最大的安全风险点（CIA：保密性、完整性、可用性）

### 数据模型对比

| 模型 | 时间/代表 | 数据结构 | 联系 | 优点 | 缺点 |
| --- | --- | --- | --- | --- | --- |
| 层次模型 | 1969 IBM IMS | 树形 | 仅 1:N | 简单，完整性好 | 表达非层次联系笨拙 |
| 网状模型 | DBTG/CODASYL | 网状图 | M:N（复合） | 描述真实世界更直接 | 结构复杂，DDL/DML 难 |
| 关系模型 | 1970 E.F.Codd | 二维表 | 任意 | 数学基础强，简单清晰 | 查询效率较低 |

### 数据模型三要素
- 数据结构：所研究对象类型的集合（静态特性）
- 数据操作：允许执行的操作集合（动态特性）
- 完整性约束：限定数据正确、有效、相容的规则集

### 数据库三级模式
- 外模式 View：用户视角的局部数据描述
- 概念模式 Schema：全部数据的整体逻辑结构
- 内模式 Storage：物理存储描述

## 第二章：关系模型

### 关系的六条性质
- 同列分量同类型，来自同一域
- 不同列可来自同一域，但属性名必须不同
- 列序、行序均无所谓
- 任意两元组不能完全相同
- 分量必须取原子值（1NF）

### 三条关系规则
- Rule 1 第一范式：列中不允许多值或内部结构（属性原子性）
- Rule 2 内容访问：只能根据属性值检索行（SQL 实际违反此规则）
- Rule 3 行唯一：任意两行不能完全相同

### 键、超键、主键

| 概念 | 定义 |
| --- | --- |
| 候选键 (Candidate Key) | 满足唯一性 + 最小性的属性集 |
| 超键 (Superkey) | 仅满足唯一性，不要求最小性 |
| 主键 (Primary Key) | 设计者从候选键中选出的一个 |
| 外键 (Foreign Key) | 引用另一表主键的属性，可空或等于被引主键值 |

### 三类完整性约束
- 实体完整性 (Entity Integrity)：主键任何属性都不能取空值
- 参照完整性 (Referential Integrity)：外键取空或等于被参照的主键值
- 用户定义完整性 (User-defined)：NOT NULL、UNIQUE、CHECK、DEFAULT 等

### 关系代数运算

集合运算（要求兼容表，列名+域+含义都一致）
- 并 $R \cup S$
- 交 $R \cap S$
- 差 $R - S$
- 笛卡尔积 $R \times S$（结果元数 $r+s$，行数 $|R| \times |S|$）

关系运算
- 选择 $\sigma_F(R)$ 或 `R where F`
- 投影 $\pi_A(R)$ 或 `R[A]`
- 自然连接 $R \bowtie S$（自动按同名同域属性等值连接，去重复列）
- $\theta$-连接：用 $>, <, =, \neq$ 等比较运算符
- 外连接：左外、右外、全外，缺失方填 NULL
- 除法 $R \div S$：找出 R 中与 S 所有行都匹配的属性值

### 除法的等价表达
$R \div S = R[X] - ((R[X] \times S - R)[X])$

其中 $X = Head(R) - Head(S)$

### 几个常考代数等价
- $R \cap S = R - (R - S)$
- $R \bowtie S$ 当 $Head(R) \cap Head(S) = \emptyset$ 时退化为 $R \times S$
- $R \bowtie S$ 当 $Head(R) = Head(S)$ 时退化为 $R \cap S$

## 第三章：SQL 查询语言

### SELECT 完整语法
```sql
SELECT [ALL|DISTINCT|TOP N] expr [AS alias] {, expr ...}
[INTO new_table]
FROM table {, table ...}
[WHERE search_condition]
[GROUP BY col {, col ...}] [HAVING condition]
[ORDER BY col [ASC|DESC] {, ...}];
```

执行顺序：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

### WHERE 子句常见条件

| 类型 | 用法 |
| --- | --- |
| 范围 | `BETWEEN low AND high`、`NOT BETWEEN ...` |
| 集合 | `IN (...)`、`NOT IN (...)` |
| 字符匹配 | `LIKE 'pattern'`，`%` 任意多字符，`_` 单字符 |
| 空值 | `IS NULL`、`IS NOT NULL`（不能用 `=`） |
| 量词 | `= ANY/SOME`、`< ALL`、`EXISTS`、`NOT EXISTS` |

### 子查询类型
- 不相关子查询：内层独立运算一次，结果传给外层
- 相关子查询：内层引用外层的列，外层每行触发一次内层执行

### EXISTS 与差运算的关系
- `NOT EXISTS` 模拟差集
- `WHERE NOT EXISTS (SELECT * FROM ...)` 表示外层与内层无对应

### 除法的 SQL 模板（双重 NOT EXISTS）
```sql
SELECT cid FROM customers c
WHERE NOT EXISTS (
  SELECT * FROM agents a WHERE a.city='New York' AND
    NOT EXISTS (SELECT * FROM orders o
                WHERE o.aid=a.aid AND o.cid=c.cid));
```
含义：找不存在某个 NY 代理 a 且该顾客没在 a 处下过订单的顾客

### 集合函数（聚合函数）
- COUNT、SUM、AVG、MAX、MIN
- 除 COUNT 外都作用于简单值集
- 聚合函数不能直接用于 WHERE，可用于 HAVING 或子查询的 SELECT

### GROUP BY 规则
- SELECT 中出现的非聚合列必须出现在 GROUP BY 中
- WHERE 在分组前过滤行，HAVING 在分组后过滤组
- HAVING 后的条件只能涉及 GROUP BY 列或聚合函数

### WITH ROLLUP / WITH CUBE
- ROLLUP：在 GROUP BY 列从右往左逐级汇总
- CUBE：所有维度组合的汇总

### 连接形式（SQL-99）

| 形式 | 含义 |
| --- | --- |
| `INNER JOIN ... ON` | 内连接，仅匹配行 |
| `LEFT OUTER JOIN` | 左表全保留，右表补 NULL |
| `RIGHT OUTER JOIN` | 右表全保留 |
| `FULL OUTER JOIN` | 双方都保留 |
| `CROSS JOIN` | 笛卡尔积 |

### 三种更新语句

INSERT
```sql
INSERT INTO table [(col,...)] VALUES (val,...) | subquery;
```

UPDATE
```sql
UPDATE table SET col=expr [, ...] [WHERE cond];
```

DELETE
```sql
DELETE FROM table [WHERE cond];
```

### 集合运算符
- `UNION [ALL]`：并
- `INTERSECT [ALL]`：交
- `EXCEPT [ALL]`：差
- 加 ALL 保留重复行，不加去重

## 第四章：完整性、视图、安全

### Create Table 列约束

| 约束 | 含义 |
| --- | --- |
| NOT NULL | 不允许空值 |
| UNIQUE | 唯一，可有多个 NULL |
| PRIMARY KEY | 隐含 NOT NULL + UNIQUE，每表一个 |
| CHECK (cond) | 行级条件检查 |
| DEFAULT val | 缺省值 |
| REFERENCES T(col) | 外键 |

候选键 = UNIQUE + NOT NULL

### 外键删除/更新动作

| 子句 | 行为 |
| --- | --- |
| ON DELETE CASCADE | 主表删除，从表对应行级联删除 |
| ON DELETE RESTRICT | 主表有引用时拒绝删除（默认） |
| ON DELETE SET NULL | 从表外键置空 |
| ON UPDATE CASCADE | 主表主键修改，从表外键级联修改 |

### 触发器语法（标准 SQL）
```sql
CREATE TRIGGER name {BEFORE|AFTER}
  {INSERT|DELETE|UPDATE [OF col,...]} ON table
  [REFERENCING {OLD|NEW} [ROW|TABLE] AS corr_name ...]
  [FOR EACH ROW | FOR EACH STATEMENT]
  [WHEN (cond)]
  statement;
```

### SQL Server 触发器
```sql
CREATE TRIGGER trg ON tbl
{AFTER | INSTEAD OF} {INSERT | UPDATE | DELETE}
AS
  -- 通过 inserted、deleted 两个虚表访问变化数据
  SQL_statements;
```

- inserted 表：保存 INSERT/UPDATE 后的新行
- deleted 表：保存 DELETE/UPDATE 前的旧行
- INSTEAD OF：替代触发，常用于视图
- 视图只能定义 INSTEAD OF 触发器

### 视图

定义
```sql
CREATE VIEW vname [(col,...)] AS subquery
[WITH CHECK OPTION];
```

特性
- 虚表，不实际存数据
- 数据库通过 query modification 把视图查询改写为基表查询
- WITH CHECK OPTION 禁止通过视图插入/更新会让该行不再可见的数据

### 可更新视图条件
- FROM 中只有一张表（如果是视图也必须可更新）
- 不含 GROUP BY、HAVING
- 不含 DISTINCT
- WHERE 不含引用 FROM 表的子查询
- SELECT 列表只能是简单列名，不能有表达式或重复列

### 视图的价值
- 简化复杂查询
- 屏蔽基表变化（数据独立性）
- 安全性（不同用户看不同视图）

### GRANT 语法
```sql
GRANT {priv [(col,...)] ,... | ALL PRIVILEGES}
ON {table | view}
TO {user | PUBLIC} [, ...]
[WITH GRANT OPTION];
```

权限：SELECT、INSERT、DELETE、UPDATE[(col)]、REFERENCES[(col)]

### REVOKE 语法
```sql
REVOKE [GRANT OPTION FOR] priv ON obj FROM user [CASCADE|RESTRICT];
```

### SQL Server 安全四级
- 操作系统安全
- SQL Server 登录
- 数据库使用权
- 数据库对象使用权

## 第五章：规范化（Normalization）

### 不规范设计的四类问题
- 数据冗余（同一信息多处存储）
- 修改异常（多处不一致）
- 删除异常（删一行丢失多种信息）
- 插入异常（缺主键属性无法插入）

### 函数依赖 (FD)
$X \to Y$：对任意元组 $t_1, t_2$，若 $t_1[X] = t_2[X]$，则 $t_1[Y] = t_2[Y]$

平凡依赖：$Y \subseteq X$ 时的 $X \to Y$

### Armstrong 公理
基本规则
- 包含/自反：$Y \subseteq X \Rightarrow X \to Y$
- 传递：$X \to Y, Y \to Z \Rightarrow X \to Z$
- 增广：$X \to Y \Rightarrow XZ \to YZ$

推论
- 合并：$X \to Y, X \to Z \Rightarrow X \to YZ$
- 分解：$X \to YZ \Rightarrow X \to Y, X \to Z$
- 伪传递：$X \to Y, WY \to Z \Rightarrow XW \to Z$
- 聚积：$X \to YZ, Z \to W \Rightarrow X \to YZW$

### 闭包

FD 集闭包 $F^+$：F 通过 Armstrong 公理能推出的全部 FD

属性集闭包 $X^+_F$：能由 X 函数决定的全部属性

属性集闭包算法
```
X+ := X
repeat
  for each Y -> Z in F:
    if Y ⊆ X+ then X+ := X+ ∪ Z
until X+ no change
```

### 函数依赖集等价
- F 覆盖 G：$G \subseteq F^+$
- $F \equiv G$：F 覆盖 G 且 G 覆盖 F

### 候选键计算

方法一（删属性法）
```
K := Head(T)
for each A in K:
  if (K - A)+ = Head(T) then K := K - A
return K
```

方法二（按属性位置分类）

| 分类 | 是否在候选键中 |
| --- | --- |
| 左部属性（仅出现在 FD 左边） | 一定在 |
| 右部属性（仅出现在右边） | 一定不在 |
| 双部属性（两边都出现） | 可能在可能不在 |

### 最小覆盖（极小函数依赖集）算法
- Step 1：把右边拆为单属性
- Step 2：去除冗余 FD（去掉某条后求左侧闭包仍含右侧）
- Step 3：去除左边冗余属性
- Step 4：合并左边相同的 FD（用合并规则）

### 无损分解（Lossless Join Decomposition）
分解 $T \to \{T_1, T_2\}$ 无损 $\Leftrightarrow$ 满足以下之一
- $Head(T_1) \cap Head(T_2) \to Head(T_1)$
- $Head(T_1) \cap Head(T_2) \to Head(T_2)$

即两表交集要能函数决定其中一表的全部属性

多表分解：递归判断 $((T_1 \bowtie T_2) \bowtie T_3) \bowtie ... \bowtie T_k$

### 依赖保持
分解 $\{T_1, ..., T_k\}$ 保持依赖 $\Leftrightarrow F^+ = (F_1 \cup F_2 \cup ... \cup F_k)^+$

每个 $F_i$ 是 F 投影到 $T_i$ 的属性集上得到的 FD 集

### 范式定义

主属性：包含在某个候选键中的属性

非主属性：其他属性

| 范式 | 条件 | 解决问题 |
| --- | --- | --- |
| 1NF | 属性原子，无重复组 | 基本要求 |
| 2NF | 1NF + 非主属性完全函数依赖于候选键 | 消除非主属性的部分依赖 |
| 3NF | 对每条 $X \to A$，X 是超键，或 A 是主属性 | 消除非主属性的传递依赖 |
| BCNF | 对每条非平凡 $X \to A$，X 必须是超键 | 消除主属性的传递/部分依赖 |

包含关系：BCNF $\subset$ 3NF $\subset$ 2NF $\subset$ 1NF

### 3NF 与 BCNF 的差别

| 特性 | 3NF | BCNF |
| --- | --- | --- |
| 对 X 的要求 | 超键 或 A 是主属性 | 必须是超键 |
| 是否一定保持依赖 | 可以保证 | 不一定 |
| 是否一定无损 | 可以保证 | 可以保证 |

BCNF 比 3NF 更严，但可能过度分解导致依赖不保持

### 3NF 分解算法（合成法，保持依赖且无损）
```
1. 用 F 的最小覆盖替换 F
2. S := ∅
3. 对每条 X -> Y in F:
     若 S 中没有任何关系 Z 满足 XY ⊆ Z，
     则 S := S ∪ {Heading(XY)}
4. 若 S 中所有关系都不含某候选键，
   选一个候选键 K，加 Heading(K) 到 S
```

## 第六章：E-R 建模

### 三大基本元素
- 实体 (Entity)：现实世界中可区分的对象集合（用矩形）
- 属性 (Attribute)：实体或联系的性质（用椭圆）
- 联系 (Relationship)：实体间的对应规则（用菱形）

### 属性的种类与画法

| 类型 | 画法 |
| --- | --- |
| 主标识符（主键） | 椭圆下加下划线 |
| 描述符 | 普通椭圆 |
| 复合属性 | 椭圆下挂多个简单椭圆 |
| 多值属性 | 双线椭圆 |
| 派生属性 | 虚线椭圆 |

### 联系的基数 (Cardinality)

记法 $\text{card}(E, R) = (\min, \max)$

- max-card = 1：单值参与，多则 N
- min-card = 0：可选参与，1 则强制

| 联系类型 | 含义 | 表示 |
| --- | --- | --- |
| 1-1 | 双方都单值 | 一对一 |
| 1-N | 一方多值，一方单值 | 一对多 |
| N-N | 双方都多值 | 多对多 |

### 弱实体
- 自身的存在依赖于另一强实体
- 用双矩形表示，通过双菱形与强实体相连

### E-R 转关系的六条规则

Rule 1（实体）：每个实体映射为一张表，单值属性映射为列

Rule 2（多值属性）：单独建一张新表 (主键, 多值属性)，主键为两者组合

Rule 3（M:N 联系）：建立独立表，含双方主键 + 联系自身的属性

Rule 4（N:1 联系）：在 N 端添加 1 端的主键作为外键，无需独立表

Rule 5（1:1 单方可选）：在强制方加另一方主键作为 NOT NULL 外键

Rule 5'（1:1 双方可选）：单独建表存放外键对

Rule 6（1:1 双方强制）：合并两实体为一张表

### 泛化层次（Supertype / Subtype）
- 超类 + 子类（IS-A 关系）
- 全特化：超类实例必须属于某子类
- 部分特化：超类实例可不属于任何子类
- 不相交规则：每个超类实例最多属于一个子类
- 重叠规则：可属于多个子类

### 聚集
- 把联系本身当作实体，参与更高层联系
- 用于表示"联系之间的联系"

### 设计步骤
- 需求分析（确定服务对象、用户）
- 实体识别 + 必要属性
- 联系分析（基数）
- 弱实体、子类的识别
- 检查并简化
- 转换为关系模式

## 第七章：存储过程

### 存储过程的优缺点

| 优点 | 缺点 |
| --- | --- |
| 模块化编程 | T-SQL 语言能力较弱 |
| 减少网络流量（多语句一次调用） | 与开发工具集成不佳 |
| 首次执行后查询计划缓存，速度快 | 移植性差 |
| 基于函数限制访问，安全性好 | |
| 一致性、减少错误 | |

### 创建/执行/删除
```sql
CREATE PROC name [;number]
  [@param datatype = default [OUTPUT] {, ...}]
  [WITH {RECOMPILE | ENCRYPTION}]
AS
  SQL_statements
[RETURN [int_status]]

EXEC name [param=value, ...]      -- 执行
DROP PROC name                    -- 删除
EXEC sp_helptext name             -- 查看源码
EXEC sp_depends name              -- 查看引用对象
ALTER PROC ...                    -- 修改
```

### 参数类型
- 输入参数：可设默认值，调用时可省略
- 输出参数：声明 OUTPUT，调用时变量也要加 OUTPUT
- 状态码：用 RETURN 返回整数，0 表示成功，SQL Server 保留 -1 至 -99

### 临时表在存储过程中
- `#temp`：局部临时表，过程退出自动删
- `##temp`：全局临时表，需显式删除或用户断连后删

### 存储过程组
同名不同号：`name;1`、`name;2`，可一起删除

### 远程调用
```sql
EXEC server.db.owner.proc_name
```

### 系统存储过程
- 名以 `sp_` 开头
- 存放在 master 数据库
- 拥有者为 dbo

## 第八章：索引

### 索引的本质
- 索引项：(索引键, ROWID)
- 按键值排序存储在磁盘上
- 目的：减少磁盘 I/O 次数

### 索引键 vs 关系键

| 维度 | 索引键 | 关系键 |
| --- | --- | --- |
| 顺序 | 有序 | 无序 |
| 是否唯一 | 不必唯一（除非 UNIQUE） | 候选键唯一 |
| 目的 | 加速查询 | 标识行 |

### CREATE INDEX 语法
```sql
CREATE [UNIQUE] [CLUSTERED|NONCLUSTERED] INDEX name
  ON table (col [ASC|DESC] {, ...});
DROP INDEX name;
```

### 磁盘访问时间组成
- 寻道时间：磁盘臂移到指定柱面 ≈ 0.008 s
- 旋转延时：转到指定扇区 ≈ 0.004 s
- 传输时间：读写页面 ≈ 0.0005 s

总访问时间约 12.5 ms，比内存访问慢百万倍

### 二分查找的瓶颈
百万行索引项二分查找最坏需 $\lceil \log_2 1000000 \rceil = 20$ 次比较，前 12 次几乎都跨页面，最少 12 次磁盘 I/O

### B 树结构

性质
- 每个节点对应一个磁盘页
- 叶节点存 (keyval, ROWID)
- 内部节点存 (分隔键, 子节点指针)
- 除根节点外都至少半满
- 同一深度的所有叶节点构成有序链

层数公式：$k = \lceil \log_n M \rceil$，n 为节点扇出，M 为行数

### B 树查找复杂度
扇出 256、百万行：$\lceil \log_{256} 1000000 \rceil = 3$ 次 I/O，远少于二分的 12 次

### 节点空间分配
- PCTFREE：建索引时每节点的预留空间，默认 10%
- 节点分裂：插入时若空间不足，分裂为两个节点

### 聚簇索引 vs 非聚簇索引

| 特性 | 聚簇索引 | 非聚簇索引 |
| --- | --- | --- |
| 行物理顺序 | 与索引键一致 | 与索引键无关 |
| 叶节点 | 直接是数据行 | 存 ROWID 指向数据行 |
| 每表数量 | 至多 1 个 | 多个 |
| 范围查询 | 快（同一页面多行） | 慢（多次随机 I/O） |
| 占用空间 | 小 | 较大 |
| 建立速度 | 慢（需重排数据） | 快 |

B 树主索引一定是聚簇索引

### 索引设计权衡
- 创建过多索引：插入/更新成本高，占空间
- 应建索引的列：经常 WHERE/JOIN/ORDER BY 的列
- 不宜建索引的列：频繁更新的、列值重复度高的、表很小的

## 第九章：事务与并发控制

### 事务定义
事务是一组数据库操作的逻辑单元，DBMS 保证 ACID

```sql
BEGIN TRANSACTION
  op1; op2; ... opN;
[COMMIT WORK | ROLLBACK WORK]
```

### ACID 性质

| 性质 | 含义 | 实现 |
| --- | --- | --- |
| 原子性 (Atomicity) | 全做或全不做 | Recovery 系统 |
| 一致性 (Consistency) | 从一致状态到一致状态 | 程序员 + 完整性约束 |
| 隔离性 (Isolation) | 并发事务相互独立 | 并发控制 |
| 持久性 (Durability) | 提交后修改永久保存 | Recovery 系统 |

### 事务执行模式（SQL Server）

| 模式 | 特点 |
| --- | --- |
| 自动事务 | 每条 SQL 自动包成事务 |
| 显式事务 | `BEGIN TRAN ... COMMIT/ROLLBACK TRAN` |
| 隐式事务 | `SET IMPLICIT_TRANSACTIONS ON`，遇 DDL/DML 自动开启，需手动结束 |

### 保存点
```sql
BEGIN TRAN mywork
  -- ...
  SAVE TRAN savepoint1
  -- ...
  ROLLBACK TRAN savepoint1   -- 仅回滚到保存点
COMMIT TRAN
```

### 并发引发的四类异常

| 异常 | 含义 |
| --- | --- |
| 丢失修改 (Lost Update) | T1、T2 同时读改写，后写覆盖前写 |
| 脏读 (Dirty Read) | 读到未提交事务写入的数据 |
| 不可重复读 (Non-Repeatable Read) | 同一事务两次读同一行数据值不同 |
| 幻读 (Phantom Read) | 同一查询条件两次读到的行集不同 |

### 隔离级别与异常对照

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
| --- | --- | --- | --- |
| Read Uncommitted | 可能 | 可能 | 可能 |
| Read Committed | 否 | 可能 | 可能 |
| Repeatable Read | 否 | 否 | 可能 |
| Serializable | 否 | 否 | 否 |

设置：`SET TRANSACTION ISOLATION LEVEL <level>`

### 冲突操作的判定
两操作 $X_i(A), Y_j(B)$ 冲突 ⇔
- $A = B$（同一数据项）
- $i \neq j$（不同事务）
- 至少有一个是写

三种冲突形式
- $R_i(A), W_j(A)$
- $W_i(A), R_j(A)$
- $W_i(A), W_j(A)$

### 优先图（Precedence Graph）
- 顶点：已提交事务
- 边 $T_i \to T_j$：H 中存在冲突操作 $X_i, Y_j$ 且 $X_i$ 在 $Y_j$ 前

### 可串行化定理
H 是冲突可串行化 $\Leftrightarrow$ 优先图 PG(H) 无环

### 锁的类型

| 锁 | 别名 | 特性 |
| --- | --- | --- |
| X 锁 | 排他锁、写锁 WL | 独占，其他事务任何锁都不能加 |
| S 锁 | 共享锁、读锁 RL | 多个事务可同时持 S 锁 |

锁相容矩阵

| 当前持有 \ 申请 | S | X |
| --- | --- | --- |
| - | √ | √ |
| S | √ | × |
| X | × | × |

### 两段锁协议 (2PL)
- 阶段 1（增长期）：只能加锁
- 阶段 2（收缩期）：只能解锁
- 一旦释放任何一个锁，不能再申请新锁

定理：遵循 2PL 的调度一定是冲突可串行化的

### 死锁
- 多个事务循环等待对方持有的锁
- 解决：超时、检测（等待图找环）、回滚牺牲事务

### 调度的恢复性

| 调度类型 | 条件 | 含义 |
| --- | --- | --- |
| 可恢复调度 | 若 T2 读 T1 写的数据，T1 必须先于 T2 提交 | 防止读已回滚的数据 |
| 无级联调度 | 若 T2 读 T1 写的数据，T1 必须在 T2 读之前已提交 | 避免一个事务故障引起一系列回滚 |

无级联 ⊂ 可恢复

### 故障类型
- 事务故障：运算溢出、并发死锁导致撤销
- 系统故障：操作系统/硬件错误，内存丢失但磁盘完好
- 介质故障：磁盘损坏，需用备份恢复
- 计算机病毒

### 恢复技术
- 数据转储（备份）
  - 静态转储 vs 动态转储
  - 海量转储 vs 增量转储
- 日志文件 (Log)
  - 必须先写日志，后写数据库（WAL 原则）
  - 登记顺序严格按事务执行的时间顺序

### 三种日志

| 类型 | 内容 | 用途 |
| --- | --- | --- |
| UNDO Log | 仅 Before Image | 回滚未提交事务 |
| REDO Log | 仅 After Image | 重做已提交事务 |
| UNDO/REDO Log | 两者皆有 | 通用恢复 |

### 检查点 (Checkpoint)
作用：缩短崩溃恢复时所需扫描的日志范围

提交一致检查点的步骤
- 暂停新事务，等所有当前事务提交
- 写出日志缓冲到磁盘
- 写出所有脏数据页到磁盘
- 写入 (CKPT) 标记

恢复时只需处理上一个检查点之后的日志

### 备份与恢复 SQL（SQL Server）
```sql
EXEC sp_addumpdevice 'disk', 'MyBKDB', 'c:\MyBKDB.bak';
BACKUP DATABASE stuInfor TO MyBKDB;
RESTORE DATABASE stuInfor FROM MyBKDB;
```
